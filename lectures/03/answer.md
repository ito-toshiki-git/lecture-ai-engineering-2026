## 演習

### 第1回の単発回答とエージェントの回答の違い

同じ質問「AIE2026の講座の宿題にある『3レベル』とは何ですか？」を使った．AIE2026はこの講座を指す教材内の呼称である．

第1回の2026年10月23日の実測では，資料を検索しないモデルが一般的な難易度の説明を返し，「全員が必ずクリアすべき基本レベル」など，講座の完了条件と一致しない補足をしていた．今回，同じ単発呼び出しを改めて実行すると，講座の資料にアクセスできないと断ったうえで，複数の一般的な「3レベル」の例を挙げた．講座固有の定義を確認できたわけではない．

一方，エージェントは `search_glossary(query='3レベル')` で用語集を調べ，「基礎・実装・発展」「どれか一つに取り組めば完了」と回答し，関連回として第1回を示した．これは `data/glossary.json` の定義と一致する．単発呼び出しとエージェントはモデル名をそろえたが，指示文や道具も異なるため，モデルそのものの性能差を測った比較ではない．

### 実行記録に現れた道具と呼び出し回数

LLM（Large Language Model，大規模言語モデル）は，文章を生成したり，道具の呼び出しを選んだりするモデルである．下表の `requests` はモデルへの問い合わせ回数であり，道具の実行回数とは異なる．

| 質問・操作 | 道具の名前と引数 | requests | 道具の実行回数 |
|---|---|---:|---:|
| 単発で3レベルを質問 | なし | 1 | 0 |
| エージェントに3レベルを質問 | `search_glossary(query='3レベル')` | 2 | 1 |
| LoRAとQLoRAの違いを質問 | `search_glossary(query='LoRA')` と `search_glossary(query='QLoRA')` | 2 | 2 |
| 第2回の確認問題を依頼 | `make_quiz(lecture=2)` | 2 | 1 |
| 第3回の学習記録の保存を拒否 | `save_learning_log(lecture=3, content=下記の本文)` の要求 | 2 | 0 |
| 同じ保存を承認 | 同上 | 2 | 1 |
| 同じ保存をもう一度承認 | 同上 | 2 | 1（新規作成なし） |

LoRAはLow-Rank Adaptation（低ランク適応），QLoRAはQuantized Low-Rank Adaptation（量子化を組み合わせた低ランク適応）である．比較の実測では二つの検索要求が一度のモデル応答で出たため，検索が2回でもモデルへの問い合わせは2回だった．7種類の確認全体では，モデルへの問い合わせは計13回である．

拒否の場合にも実行記録には道具の「要求」と拒否を伝える「戻り値」が残るが，保存関数は実行されていない．`tool_calls` も0であり，ファイルは作られなかった．

### 追加した確認問題の道具

`app/tools.py` に `make_quiz(lecture: int) -> str` を追加し，`app/agent.py` で登録した．`lecture` は講義の回数，`int` はinteger（整数），`str` はstring（文字列）を表すコード上の表記である．

指定された回の用語を用語集から集め，その中から一つを選び，問題と定義を返す．第0回など該当用語がない場合は，理由を返して終了する．説明文であるdocstring（documentation string）には，「第2回の確認問題を出して」のように復習問題を求められたときに使う，と記載した．モデル全体への指示にも確認問題を求められたらこの道具を使うよう追記した．

実測では `make_quiz(lecture=2)` が呼ばれ，「ファインチューニング」の意味・目的を説明する問題が出された．Fine-Tuning（ファインチューニング）とは，既に学習済みのモデルを，目的に合ったデータで追加学習することである．問題だけを依頼したため，利用者向けの返答には解答を出さなかった．

## 宿題：実装

### やったこと

`save_learning_log` を追加し，講義の回数と保存本文を `learning_log/` に保存するようにした．JSON（JavaScript Object Notation，項目名と値などでデータを表す形式）で記録する．

保存機能は `requires_approval=True`（承認を必要とする設定）を付けて登録し，出力の候補に `DeferredToolRequests`（実行を保留した道具の要求）を加えた．保存要求が出ても，この時点では保存関数を実行しない．

CLI（Command Line Interface，文字のコマンドと入力で操作する画面）には保存先・講義の回数・本文を表示する．`y` または `yes` の入力だけを承認とし，空入力・`n`・その他の入力は拒否にする．その判断を `DeferredToolResults`（保留した要求に対する承認・拒否などの結果）に格納し，直前までの会話履歴とともに渡して続行する．入力の終端や中断操作では，保留中の保存を実行せず終了する．複数の保存要求にも一件ずつ確認する．

承認の作り方は [Pydantic AI公式文書](https://pydantic.dev/docs/ai/tools-toolsets/deferred-tools/) を参照し，配布バージョンで動作を確認した．

### 工夫した点

- **保存先を固定した．** モデルにファイルの場所を自由に選ばせず，`learning_log/` 内に保存する．保存する本文をファイル名として使わない．
- **二重保存を防いだ．** 同じ講義回と完全に同じ本文から同じファイル名を作り，既存ファイルの内容も確認する．同一なら `already_saved`（既に保存済み）を返し，作り直さない．別の内容なら別の記録になる．
- **既存記録を上書きしない．** 新規作成専用の方法を使い，既存内容が違う・壊れている場合はエラーにする．空本文，5000文字を超える本文，用語集にない回数も保存しない．
- **無限に繰り返させない．** 中断・再開を通して，モデルへの問い合わせ10回，道具の実行12回，承認待ち3巡を上限とした．
- **返答だけで成功を判定しない．** 実行前後のファイル数・内容を比較した．個人の学習記録を共有しないよう，配布された `.gitignore`（共有する変更から除くファイルの指定）の設定を維持した．実測結果に含めた本文は検証専用の短文である．

### 結果

保存を試した本文：

> エージェントではモデルが道具を選び，実行はプログラムが行う．

| 条件 | 保存前 | 保存後 | 確認結果 |
|---|---:|---:|---|
| `n` で拒否 | 0件 | 0件 | モデルも保存していないと回答 |
| `y` で承認 | 0件 | 1件 | 回数・本文が要求と完全一致 |
| 同じ本文を再び承認 | 1件 | 1件 | `already_saved`，内容と作成時刻も不変 |

自動テストは，配布分11件と追加分21件の計32件がCodespacesで成功した（`32 passed in 6.55s`）．追加分では，承認前・拒否・空入力・入力中断で保存されないこと，承認済みの本文だけが保存されること，複数要求への個別判断，二重保存，既存ファイルの保護，入力不備，書き込み失敗，繰り返しの上限，問題の出典との一致を確認した．

TestModel（テスト用モデル）とFunctionModel（指定した関数で返答を作るテスト用モデル）の検証は，実際のGeminiへの問い合わせを行っていない．この検証と，前述の実測を区別している．手元のWindowsでは配布の道具接続テスト2件がuvを見つけられず失敗したため，指定環境のCodespacesで全32件が通ることを確認した．

### 気づき・疑問と残る課題

1. 道具の説明文は，モデルが使い方を選ぶための情報である．しかし「確認してから保存」と文章で指示するだけでは，実行を確実に止められない．承認の判定はモデルの外側のプログラムに置く必要がある．
2. 保存済みと答えたかどうかと，実際に保存されたかは別である．今回も再保存時の道具は `already_saved` を返したのに，モデルは単に「保存しました」と答えた．二重保存は防げているが，「既にあるため追加しなかった」と利用者に説明する点には改善の余地がある．
3. 検索結果が正しくても，最終回答の表現は完全ではない．LoRAとQLoRAの比較回答の末尾に不要な `</code>` が残った．用語検索が動いたことと，回答全文の品質を分けて評価すべきである．
4. 二重保存を防ぐ対象は，同じ講義回と完全に同じ本文に限る．言い換えや空白の違いまで同一視していない．また，保存した記録を次の会話へ自動的に読み戻す機能は今回の課題には含めていない．保存はモデルの追加学習でもない．
5. 通常利用の承認はプログラム側で強制しているが，Pythonの保存関数を直接呼べる人まで制限する認証機構ではない．複数利用者向けのサービスへ拡張する場合は，利用者ごとの保存先と権限の設計が別途必要になる．

## 再現手順

通常利用では次のように実行する．保存の確認画面で内容を読み，許可するときだけ `y` を入力する．

```bash
uv sync --frozen
uv run python -m app.agent --list-tools
uv run python -m app.agent --trace "第2回の内容から確認問題を1問出して"
uv run python -m app.agent --trace "第3回の学習記録として，承認前は保存しないことを学んだ，と保存してください"
uv run pytest -q
```

`--list-tools` は道具一覧，`--trace` は呼び出しの記録を表示する指定である．一覧と自動テストは認証キー不要，実際の質問では認証キーを使う．

`uv run python scripts/check_lec03_live.py` は実測用であり，実際の利用枠を使う．既存の学習記録がある場合は停止するため，別の作業コピーで試す．この実測用スクリプトは承認・拒否を自動入力するが，通常のアプリには自動承認の指定を設けていない．
