### 実装の仕組み

`client.chats.create(model=MODEL)` で1つの会話セッションを作り，同じセッションの `send_message()` を繰り返し呼ぶ．SDKが過去の質問と回答を次のリクエストに含めるため，「先ほどの説明を短くして」といった文脈を必要とする追加質問を送れる構造になる．モデルの回答を単なる文字列に変換して履歴を作り直すことはせず，SDKの履歴管理を使う．

- `/reset`：新しい会話セッションを作り，以前の履歴を次の質問に含めない．
- `/exit`：対話を終了する．入力待ち中のEOFやCtrl+Cでも終了できる．
- 空の入力：APIを呼び出さず，再入力を待つ．
- APIエラー：説明を表示し，利用者が次の入力を選べるようにする．エラー後にアプリ側で質問を自動再送しない．
- 履歴の保持範囲：プログラムの実行中だけであり，終了後は保持しない．履歴をファイルへ保存する機能は追加していない．

### 実行手順

単発質問：

```bash
uv run python -m app.ask "LoRAとは何ですか？"
uv run python -m app.ask "AIE2026の講座の宿題にある「3レベル」とは何ですか？"
```

会話を続ける：

```bash
uv run python -m app.ask --chat
```

起動後，次を1行ずつ入力する．

```text
合言葉は青いペンギンです．覚えてください．返事は一文でお願いします．
先ほどの合言葉を答えてください．回答は合言葉だけにしてください．
/reset
先ほどの合言葉を答えてください．分からない場合は分からないと一文で答えてください．
/exit
```

同じ手順を再実行しても，回答やトークン数が完全に同じになるとは限らない．

### 気づき・疑問

会話を続けるには，画面に過去の発言を表示するだけでなく，その内容を次のAPI呼び出しに渡す必要がある．また，会話履歴が増えるほど入力も増えるため，長い対話ではトークン数や利用上限を意識する必要がある．履歴をリセットする機能は話題を切り替えるだけでなく，渡す情報を整理する役割も持つ．講座固有の質問では一般論による補完が見られたため，会話を続けられることと，根拠に基づいて正確に答えられることは別だと分かった．
